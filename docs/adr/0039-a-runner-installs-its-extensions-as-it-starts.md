# A Runner installs its extensions as it starts

A Runner runs its jobs' agents with Pi coding-agent extensions through the extension adapter (ADR 0038), those in a folder its operator names in `RUNNER_EXTENSIONS`, and none without one. The folder is an ordinary npm project: its `package.json` lists the extensions as dependencies, its `package-lock.json` pins every package, and its `pi-agent` folder holds their settings, which the Runner gives them as Pi's agent directory. The image ships one, which Compose and `elflodge stack` name: pi-web-access, so jobs, whose commands have no network, can read the web. A deployment that changes it does what an operator does: copies the folder, edits it and names its copy; the stack gives the Runner pi-web-access's settings with search on, in place of the image's, when its user names search providers.

As it starts, before it registers or recovers a job, the Runner copies the folder into a folder of its data directory named after a hash of its files and Node's module ABI, installs it there with `npm ci --omit=dev`, which installs exactly the lockfile's versions and checks their hashes, and bundles it; a set already installed is reused, so a restart needs no registry, and earlier sets are removed. It refuses to start, naming each extension and why, when the folder has no lockfile or an extension cannot be installed or bundled, and when the folder and the data directory contain one another, as the copy would copy itself or the install overwrite the folder. The settings are copied at every start, so the folder is their only source. npm installs with `legacy-peer-deps`, as Pi's own installs do, so the Pi packages extensions declare as peers come from Pi.

One extension host serves all of a Runner's jobs. Each job's conversation gets the extensions once it is open and its run has not closed, and before its input is submitted; the extensions close when the job's work stops, before its end is written, so nothing their shutdown handlers start lands after it, and on an interrupt after the journal closes, so nothing reaches a job that is to carry on. A job fails, its end recorded in its journal, when an extension reports an error as it loads in it, before its first model request, and when its extensions are lost after their worker exits, which the adapter reports per conversation it attached, as every job's root conversation has the same ID. The extensions are opened uninterruptibly, so a job paused while they open still closes them. Recording a pause or a cancel opens no extensions. A job's input is submitted directly rather than through Pi's `input` handlers.

Extensions are trusted as the Runner is: they run in its process with its files, environment and network, while their commands run in the job's sandbox. A key in the Runner's environment is not a choice to spend through it, so the image's settings for pi-web-access spend nothing and send nothing to a service the operator did not choose: web search is off, leaving out its tools, until the operator turns it on and names its providers, as without that list it would use any provider it finds a key for, the Runner's own model provider among them, and keyless ones the model can name; pages are fetched directly, whatever fetchers a later version or a configured service would add; PDFs are converted locally; answering questions about a page with a model is off; YouTube, which uses Gemini, and video, which reads local files anywhere on the host, are off. What extensions spend once chosen, such as search fees or their own model calls, falls outside a job's model budget. The Runner's own extension refuses searches that ask for a summary, which pi-web-access writes with a model on the Runner's credentials, or name the search provider's model; the settings' workflow and models stay the operator's choice. It also refuses calls to pi-web-access's tools that name a proxy, which the tools check only for its scheme, so a model cannot route their requests around the guard against private addresses, nor around a configured proxy with `""`.

## Considered options

- A list of Pi package sources in `RUNNER_EXTENSIONS`, such as `npm:pi-web-access@0.47.0`: Pi installs them with `npm install`, which resolves their own dependencies afresh in a new data directory, so a set cannot be pinned, and a lockfile would be a second setting to keep in step. Pi's syntax serves a person's own Pi: it keeps the list and runs npm for someone outside any npm project, with personal and project scopes, and skips a package that fails to install.
- A default in the Runner's code: hidden where operators do not change it, and not the example they follow; a Runner started without the setting runs no extensions.
- pi-web-access as a dependency of the Runner, pinned in the workspace's lockfile: the default would take a path operators' extensions never take, so a fault in the operators' path would not show in ours.
- pnpm instead of npm: its strict layout breaks extensions that import a dependency they do not declare, which work under npm, Pi's default, with which their authors test, and operators would need pnpm to make its lockfile.
- Keyless search providers on by default: every job's queries go to a service nobody chose, under limits a batch shares.
- Starting without an extension that fails to prepare, with a log line: the operator who configured it would not see that jobs ran without it, and their results would depend on what happened at start.
- Logging an extension that does not load in a job and carrying on: the job's whole run is paid for without what the operator configured, seen only in the Runner's log.
- An extension host per job: a worker set and the extensions' modules for each job, against the adapter's sharing, to tell jobs apart where a callback per conversation does.
- Routing a job's input through `input` handlers: the transformed input would have to be journaled so that a recovered run does not transform it again, a design of its own, for no extension the Runner ships.
- Filtering the environment extensions see: code that reads the Runner's files and asks its model registry for credentials is not isolated by it.

## Consequences

A changed set installs in a few seconds more at start, about 7 s and 90 MB for pi-web-access in the image. Updating an extension means updating the folder's lockfile, which npm, Renovate or Dependabot do. A local extension must sit inside the folder, as the folder is copied before it is installed. What extensions write in their agent directory does not survive a restart. The guard, the image's settings and the settings the stack writes name pi-web-access's tools, providers and settings, so each upgrade of it rechecks them. Reconsider the refusal if operators need optional extensions, input routing when an extension the Runner ships needs `input`, and the proxy guard when pi-web-access can lock its proxy without one configured.
